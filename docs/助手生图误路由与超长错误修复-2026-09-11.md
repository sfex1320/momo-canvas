# 助手生图误路由与超长错误修复

问题链路：助手绘画选“默认” → 新节点省略 modelId → addNode 合并上次模型记忆 → 实际请求旧中转站 → 裸 PNG Base64 被当相对 URL → 请求构建错误包含整张图片编码 → 节点和日志各保存数百万字，拖慢布局与持久化。

修复：

- 助手新建生图节点显式覆盖 modelId，未选时写 undefined，跟随设置的绘画默认。
- 默认模型选择器显示实际模型名称；自定义协议区分编码、Data URL、绝对和相对网址，编码字段直接生成图片 Data URL。
- 错误在统一转换、节点写入、节点显示、通知与日志入口限长；清理先取有界前缀再替换编码，防止清洗本身处理巨大字符串。
- 启动和热更新后压缩当前、其它画布、归档及撤销历史中的旧错误；保留节点、媒体和连线。

本机恢复：应用已退出后，先备份 boards.json 与 runlogs.json，再修复这次两条超长记录，并将两个误路由的失败节点改回跟随默认。逐字段比较确认仅两条错误与两条节点模型选择变化，其余画布内容一致。备份位于 AppData/site.jinpengi.momo/recovery/image-errors-20260911-002303。画布文件从 15,072,403 字节降至 2,163,181；运行日志从 13,105,616 字节降至 33,925。

验证：`pnpm build` 与最终 TypeScript 检查；独立浏览器 `scripts/qa/image-routing.html`（仅允许 [::1]:1441）9 项回归通过，包含实际 genImageOnCanvas → runFlow → 自定义生图服务链路，网络由人工响应替代，不消耗生成额度。验证 Codex 默认路由、旧参数记忆隔离、PNG/JPEG/URL 解析、650 万字错误限制、旧错误清理保留生成结果。没有重跑用户的收费生图任务。
