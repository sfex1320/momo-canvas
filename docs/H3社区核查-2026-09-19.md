### 本机参数与作者建议的差异

本机 [2026-09-12 升级记录](<G:/ciomfyui AI/ComfyUI-aki-v3/H3_Upgrade_20260912/升级完成与使用说明.md>) 第 50 行明确记录：当时 GitHub 规格表尚未补全，Ref2V 八步权重头的 `base_model` 仍写 FL2VA，故采用 Ref2VA 主模型、shift **6/3**、1344×768 做本机验证；第 58 行记载该次后端执行成功，耗时 125.33 秒。该记录只证明组合能完成生成，不证明它优于其他 shift。

本次重新读取 [LightX2V 作者发布帖 #51](https://huggingface.co/lightx2v/Minimax-h3-Turbo/discussions/51)，正文明确写的是 **Ref2V 八步 768p v1.0：video shift 12、audio shift 3、Euler、8 步**，不是误用了四步说明。发布帖时间为 9 月 3 日；本次并未取得编辑历史，不能声称这项建议是 9 月 12 日之后才更新。

**本轮只整理入口，不改 `KfERil-G` 的 6/3 参数。** 12/3 应作为后续同图、同提示词、同种子、同步数的对照候选，核对动作、身份、音频和耗时后再决定默认值。当前没有本机 12/3 的成片证据，不把已测 6/3 标成故障，也不把 12/3 写成已验证升级。

另一个需区分的地方：上述表格的 Ref2VA 四步是上游基线建议；本机 `04_多参考_544p四步` 历史记录实际使用 **Singularity v1.3 + Ref2V Turbo v0.1**，并已完成生成。本轮保留此实际组合，不静默换回原生 Ref2VA。

## 配套与精简原则

- 原生 FL2VA 承担文生、首帧和首尾帧；Ref2VA 用于图片、视频、音频参考。官方入口分别是 `MiniMaxH3ImageToVideo` 和 `MiniMaxH3ReferenceToVideo`。分辨率应对齐 32；16:9 常用 1344×768。视频为 24fps，帧数按 `17k+5` 对齐，5 秒常落到 124 帧。[原生教程](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-native)、[作者使用说明](https://github.com/ModelTC/Minimax-H3-Turbo/blob/main/COMFYUI_SETUP_AND_INFERENCE.md)
- LightX2V 示例只需核心节点，要求 ComfyUI ≥0.31.0。LoRA 文件名、步数和两个 shift 必须成套设置；已有这些流程时，没有必要再装一套同功能包装节点。[使用说明](https://github.com/ModelTC/Minimax-H3-Turbo/blob/main/COMFYUI_SETUP_AND_INFERENCE.md)
- Comfy-Org 推荐能使用 PyTorch cu130 时优先 `int8_convrot`，不能用时才选择 `fp8_scaled`。其 `nvfp4_awq` 文本编码器不要求 Blackwell。可优先保留一套已验证的编码器和两只 VAE，FL2VA/Ref2VA 共用；显存与现有依赖未核实前，不强制换量化版本。[Comfy-Org 模型卡](https://huggingface.co/Comfy-Org/MiniMax-H3)
- SageAttention 是官方文档列出的可选加速，需 wheel 与 PyTorch/CUDA 匹配；可用 KJNodes 补丁节点或全局启动参数。官网的速度描述不能当作本机承诺，部分层回退 PyTorch attention 属预期。[Comfy H3 总览](https://docs.comfy.org/tutorials/video/minimax/minimax-h3)
- Spectrum 通过预测跳过部分 Transformer 计算，作者明确说明它是近似加速，会改变去噪轨迹。先把基线跑稳定，再单独 A/B；不建议为了四步流程默认叠加多套缓存。[作者仓库](https://github.com/xmarre/ComfyUI-Spectrum-MiniMax-H3)

## 新路线：可研究，不默认增加负担

**Alibaba PAI PDD 八步**：2026-08-26 建仓，FL2VA 和 Ref2VA 各有配对权重。它带并行解码头，不等同于普通加速 LoRA。[官方模型卡](https://huggingface.co/alibaba-pai/MiniMax-H3-Acc-LoRAs)

作者节点 `ComfyUI-MiniMax-H3-PDD-Acc` 要求核心 ≥0.33.0，文件放 `models/pdd_acc/`，使用专用 Apply 与其 SIGMAS，Euler、CFG 1、shift 12/3。常规 LoRA 加载器可能丢失解码头。新增它会引入独立采样路线，适合单独备选测试，不能直接替换 LightX2V 流程的文件名。[节点作者 README](https://github.com/Jalen-Brunson/ComfyUI-MiniMax-H3-PDD-Acc)

**FastVideo FastH3 8-Step V2**：作者模型卡要求 VSA-H3，并指出 video shift 是 10；其 scope 明确仅 T2VA，FL2VA 与 Ref2VA 未蒸馏。[作者模型卡](https://huggingface.co/FastVideo/FastVideo-FastH3-8-Step-V2)

Comfy 官方教程要求 ≥0.36.0，提供八步 V2 文生和首尾帧模板，但这与作者关于 FL2VA 未受训的范围说明存在差异。接口能连接不代表作者已验证该条件；两方均没有把它作为 Ref2VA 替代。为本项目多参考主线精简配置时，暂不新增这套大模型。[Comfy 教程](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-fastvideo)、[Comfy 格式权重](https://huggingface.co/FastVideo/FastVideo-FastH3-Comfy)

**更多节点不等于必须安装**：MiniMax 组织下的社区集成索引还列出 VDN、Fun Control、长视频与其他加速路线，但该索引自述并非完整兼容表；只有明确需要姿态/深度控制或长视频任务时再选相应路线。[集成索引](https://github.com/MiniMax-AI/awesome-minimax-h3-integration)

## 绘世二次点击与官方启动路线

官方 Windows Portable 解压后直接运行 `run_nvidia_gpu.bat` 即启动服务，内部是便携 Python 执行 `ComfyUI/main.py`。因此已有可用 Python 和主程序的安装，可以采用经本机验证的直接启动入口，不必为了省一次点击重装或重下模型。官方还支持 `extra_model_paths.yaml` 共享已有模型目录。[官方便携版文档](https://docs.comfy.org/installation/comfyui_portable_windows)

当前官方 Comfy Desktop 是多实例管理器，提供安装和更新管理；它仍有实例管理界面，不能仅凭“官方桌面版”保证没有第二次操作。用户要的是 MOMO 一键启动服务时，优先验证 MOMO 现有直启能力与本地运行环境。[官方 Windows 桌面文档](https://docs.comfy.org/installation/desktop/windows)
