# MOMO 软件审查、流程优化与竞品调研

> 后续更新：原先列出的六组改造已在收尾轮落地，当前功能与验收结果见 [改造收尾验收](改造收尾验收-2026-09-07.md)。本文保留当轮历史记录。

日期：2026-09-06。范围：现有工作区源码、浏览器开发预览、确定性回归，以及 LibTV / Lovart 官方产品资料。保留七工位与用户已有改动；未执行发行版打包、付费生成或真实项目覆盖。

## 结论

MOMO 已有较完整的创作能力，主要问题是入口多、上下文不够明确，以及不同执行路径对确认、取消、素材、尺寸的处理不一致。此次先修用户明确指出的宫格和连续生图，再补 3D 常用操作、导演流程导引及平面拆件。

连续第二张图的问题不能只靠一句提示词修复。现有代码已有「口头承诺后复核动作」补丁，但等待确认时输入被禁用、参考图来源不稳定、停止后等待锁未闭合等问题仍会影响连续使用。现在补齐这些环节，真实助手引擎配模拟协议的连续两轮测试通过；实际服务商与用户原会话未重放，不能据此保证任何模型组合均不再失败。

## 已落实的修复与使用路径

### 宫格：完整拆分、完整重拼

以前同时存在圆角、间隙、300/320 节点宽度不一致、把非均匀切片再裁成统一比例的问题。现在共用整数边界切原图，切片以实际宽高铺开；切片不显示圆角、阴影和尺寸角标，选中标记采用内描边，避免撑开拼图。

使用：图片宫格切分→「整图无缝拆组」。按阅读顺序选全格，无需逐个勾选。任意切线和非整除尺寸也保留全部原像素；旧行列切分入口复用相同路径。1024×769 的非均匀宫格逐像素重拼测试一致。浏览器缩放的亚像素显示仍可能有视觉细线，但输出像素不会缺缝。

历史上已经被居中裁掉的内容无法凭新布局恢复，须从原图重新拆组；现有旧切片不会被后台自动重画。

### 创作助手：第二轮生成与停止

修复内容：

- 等待确认时可以直接输入「确认生成」继续，旧卡片不能误唤醒新请求。
- 显式新附件优先；未提供新图时使用最近成图；跨轮视频动作也能引用最近图片。
- 每张结果新增「以此图继续」，把目标图片显式附到下一轮。
- 确认前固定实际绘画/视频模型与参考素材；等待期间改选模型不会让已确认请求悄悄换模型。
- 停止信号贯穿理解、确认等待与图/视频请求；取消不当成普通失败继续重试，清理等待状态后可开始新一轮。
- 关闭联网后不执行模型擅自返回的联网动作；布尔字符串 `"false"` 不再误判为真，无效数量和空提示词被过滤。
- 保留已有的动作复核逻辑：有生图意图却只有口头承诺时再次要求明确执行动作。

模拟流程已验证：第一轮出图→第二轮提出修改→模型先口头回答→复核动作→用第一轮真实图片字节请求图生图→交付第二张图；另测等待确认时停止、第三轮重新生成。取消本地等待不等于撤销服务商已受理的计费任务。

### 3D 导演台

新增素模、哑光、服装风格，头部方向细节、头发和鞋；增加墙面、圆台和展板几何物件。程序人物仍用于预演站位，精细角色可继续使用 GLB 模型入口。

新增撤销/重做、聚焦、贴地、复制、10cm/15° 吸附，支持 W/E/R、F 和 Ctrl+Z。左键环绕、右键平移与提示一致。机位预设瞄准所选角色，俯拍包含真实俯仰。彩色/深度/分区导出与机位取景框共用裁切矩形；导演自由视角导出当前全视口。

修复异步 GLB 加载后被删除实体重新出现、克隆模型共享资源释放、项目切换保留旧回调等问题。3D 参考图可以送到画布或当前分镜的手动站位参考槽；没有当前分镜时不会乱绑定。保留原来的姿势、光源、模型导入和参考导出。

浏览器已实际检查新增人物、风格切换、撤销、聚焦和机位入口。未将程序人物升级为影视角色资产，也未新增动作捕捉、骨骼动画编辑或摄影机轨迹时间线。

### 导演流程

顶栏增加「剧本→分镜→生成与选片→交付」，根据项目是否有片段、在途任务和采用版本给出下一步。七个工位仍保留，高级能力没有删除。已完成但未采用的 Take 先引导选片，不直接跳到交付。在途时提示查看进度，不重复引导提交。

「引擎就绪」改为「通道已配置」，因为填有地址不能证明 ComfyUI 在线；对话模型状态按 chat 槽实际是否有模型判断。工位错误边界按项目/工位重置，切换后可以恢复。

### 新技能：元素拆解

内置技能名为「元素拆解」。入口：图片→元素工坊→识别或圈选元素→「元素拆解·平面稿」→选择绘画模型、视图、颜色和尺寸→拆解到画布。另提供可移植的 `skills/element-decompose/SKILL.md`。

支持正面去透视、背面/底面推定；背面、底面与背景分开选色；透明或纯色背景；px 或 mm+DPI 输出。原图加局部图一起传入实际绘画适配器，逐元素生成，最终按目标像素制作画板并保留比例。单边上限8192、总量2400万像素。识别失败时仍可手工圈选。结果进资产库并成为独立节点，保存来源、视图和尺寸元数据。

实际界面回归另发现并修复：预览图适配缩放后，选框原先仍按整个容器归一化，造成错位或图片被截断。现在舞台尺寸严格跟随图片的等比可见尺寸；浏览器实测舞台与图片的 x/y/宽/高完全相同。底部复选框不再被通用输入框样式拉宽。

开始前展示模型、件数、尺寸及费用估算。可停止，已完成保留，成功项取消勾选以免重试重复花费。测试确认背面颜色进入请求，80×60mm、100DPI 输出为315×236px。

尺寸指画板尺寸，不是识别出的实物尺寸；尚未写入 PNG 的印刷 DPI 元数据。背面/底面不可见部分只能推定，真实装配尺寸、刀模、公差、CMYK/专色与可编辑文字需另做生产文件。色键去背景是近似方法，含同色元素、半透明和发丝需检查边缘。

## LibTV：适合借鉴的智能布局

调研对象为 LibTV（哩布 TV），依据[官方首页](https://www.liblib.tv/)和[官方使用指南](https://resonate.feishu.cn/wiki/Loxfw6XHziYRk0kKzdjcFfp9nhb)。指南包括以下功能：

| 官方能力 | 对 MOMO 的价值与落点 | 优先级 |
| --- | --- | --- |
| AutoLink：提示词匹配参考素材，Tab 接受、Shift+Tab 全部接受，可替换 | 输入时提出素材建议，先显示候选和真实参考序号，再由用户接受；复用 directorRefs，禁止静默误绑 | 高 |
| 剧本拆解贯穿人物/场景/道具、分镜、提示词和批量生图生视频 | 减少重复填写，让项目对象与下一步可见；此次已增加流程导引 | 高 |
| 规则分镜组、数量/画幅、整理排序 | 宫格采用共享边界与零间距布局，已落实基础修复 | 高 |
| 3D 人物/物件、姿势与本地模型、截图回画布 | 优先提升聚焦、机位、风格、输出接力，已落实相关操作 | 高 |
| 角色路径与摄影机运动预设、跟随参数 | 以后用角色路线与相机路线两套数据，添加路径、时长和关键帧；不要把机位旋转冒充完整运镜 | 中 |
| 拉片分析、指定片段重拍、字幕/停顿/节拍编辑 | 在现有 Take 和时间线上选局部重做，保留版本与声音区间；避免每次整段重做 | 中 |

这里最值得借鉴的是素材关联、对象连续性和下一步可见性。产品建议：用户选中一段，就能看清当前参考、提示词、采用 Take 和下一步；跨工位自动带着该片段走。该建议是结合 MOMO 代码作出的设计判断，并非宣称已复刻全部竞品功能。

LibTV 另有 [CLI 入口](https://www.liblib.tv/cli)与[官方技能仓库](https://github.com/libtv-labs/libtv-skills)。可借鉴明确输入输出的能力封装。MOMO 已有 capability 注册表，应扩展现有入口，避免另建平行执行引擎。未验证其付费配额、生成质量与取消计费行为。

## Lovart 与平面设计改进

Lovart 的优势主要是选中对象后的上下文操作、可见参考与结果编辑闭环，不只是模型数量。

| 官方能力与来源 | MOMO 对应基础 | 建议 |
| --- | --- | --- |
| Quick Edit、Touch Mark、Edit Elements 与 Edit Text，[编辑文档](https://www.lovart.ai/docs/edit-your-design/advanced-ai-editing) | 标注编辑、局部重绘、元素工坊、图层导出 | 让选中图片后的下一步更直接；把提取、重绘、平面拆件区别讲清 |
| @素材/模型/品牌与显式选择对象，[聊天工具](https://www.lovart.ai/docs/how-to-prompt/chat-tools) | 附图、模型选择、参考槽 | 每个操作显示「将修改哪张图」；此次已加“以此图继续” |
| Frame 的尺寸与多类画布对象，[画布对象](https://www.lovart.ai/docs/edit-your-design/canvas-objects) | 图片节点、组、拼接 | 增加真实尺寸画板、对齐/分布与安全区，减少依靠节点位置近似版式 |
| Brand Kit，[参考与品牌](https://www.lovart.ai/docs/how-to-prompt/adding-references) | 风格节点、Skill、项目规则 | 品牌包绑定标志、字体、标准色、禁用规则；在每次实际请求中可追溯 |
| 多角度、移动物体/修补、矢量化、样机，[图像转换](https://www.lovart.ai/docs/edit-your-design/ai-transformation) | 多角度、重绘、矢量、打光 | 整合成选中对象的任务入口；不再要求用户先理解节点类型 |
| 自定义复用技能，[Agent Skills](https://www.lovart.ai/docs/how-to-prompt/agent-skills) | 内置/导入 Skill | “元素拆解”作为具体工作技能落地，技能和执行功能各司其职 |
| PNG/JPEG、PSD、矢量 SVG 等，[导出格式](https://www.lovart.ai/docs/export-your-assets/export-formats) | PNG、分层导出、矢量流程 | 区分透明位图、生成式分层、真矢量；不要把 PSD 包装视为所有元素已可编辑 |

这些是官方文档描述，未做相同付费模型下的图像质量比较。旧宣传文章与现行编辑文档有差异时，优先采用现行文档，不根据宣传文案推断任何输入都能无损编辑。

另外，[Kittl Flows](https://help.kittl.com/ai-tools/kittl-flows/)与[样机流程](https://help.kittl.com/editing-and-design/mockup-generator/)适合借鉴“选定画板→生成变体/套用样机”的明确输入关系；[Illustrator 尺寸工具](https://helpx.adobe.com/illustrator/desktop/measure-and-align/plot-and-measure/dimension-tool-options-and-settings.html)可作为尺寸标注与单位控制的交互参考。它们不能证明 AI 从单张效果图即可得到可信生产尺寸。

Qwen-Image-Layered 可作为后续可选的生成式分层通道。[官方模型卡](https://huggingface.co/Qwen/Qwen-Image-Layered)、[论文](https://arxiv.org/abs/2512.15603)及[ComfyUI 官方教程](https://docs.comfy.org/tutorials/image/qwen/qwen-image-layered)表明它会重建合成图与 RGBA 层；它不是无损 Photoshop 图层恢复器，也不是背面结构推理器。适合复用现有 ComfyUI 模板输入输出，不应默认替换保像素裁切。

本地设计与品牌类 Skill 更适合提供设计约束、排版审阅和品牌一致性规则；提示词 Skill 本身不能代替图层编辑器、尺寸引擎或模型适配器。本次元素拆解同时提供技能规范和实际执行入口，避免只有提示词没有可操作功能。

## 后续优先级与尚存问题

以下未冒充已完成的功能：

1. **明确编辑对象与可见计划**：统一助手、AI 制图和画布的参考卡片，展示本次目标、模型、尺寸、参考顺序与产物位置；先建议再接受。实现范围应复用当前执行/预算系统。
2. **品牌包＋真实尺寸画板**：面向文化墙、美陈增加毫米画板、出血/安全区、缩放比例、DPI 元数据与尺寸清单。尺寸由用户/文件输入，不从透视效果图猜测。
3. **批量失败项续跑**：把此次拆件的“已完成保留”扩展为统一任务状态；助手通过通用工具执行时，仍需逐能力完善远端取消和失败恢复。
4. **3D 起始模板和轨迹**：对话站位、产品展台、展墙可作为下一批完整模板；人物/相机关键帧分开编辑，并先做预演导出再接视频模型。
5. **局部重做与版本对照**：在已有 Take 和时间线之上增加明确片段区域重做、变化范围和版本比较；保持旧结果可恢复。
6. **性能与维护**：完整构建通过，但主包约1.66MB、3D包约710KB（压缩前），仍有混合静态/动态导入和大块告警。应按用户路径拆加载边界并实测冷启动，不靠提高告警阈值掩盖问题。

其他保留限制：旧的色键拆层并非语义精确抠图；现有高清重绘路径与新平面拆件的停止/恢复尚未完全统一；通用工具、语音、所有协议组合和原生 Rust 导出没有覆盖本次全部运行验证。此次是重点链路的系统审查与修复，不是对整套软件作“零 bug”保证。
