# 图像矢量化、本地放大与导演台整理

调研与验收：2026-09-09 至 2026-09-10。结论面向 MOMO 的文化墙、纯色海报和混合海报，不把论文榜单当作用户图片的效果保证。

## 当前结论

纯色块、圆弧、直线、标志优先试「受限色盘 → 轮廓 → 几何修正 → SVG → 目标尺寸重渲染」；照片和材质区域才走保真超分。文字另存原文与排版，能匹配字体时排成文字层，无法匹配时保留轮廓或原像素。这是建议的后续组合架构，本次没有把它伪装成已实现的一键流程。

不推荐整张文化墙连续通过多个锐化模型。已经丢失的笔画、圆弧位置不能仅靠放大倍率找回来。本次不接入 Qwen-Image-Layered，也不采用其分层方式。

## 软件现状（已查代码与本机文件）

- 注册表：`src/core/localModelRegistry.ts`；路由：`src/core/runner.ts`；本地实现：`src-tauri/src/sr.rs`、`enhance2.rs`。当前就是 Rust + ONNX 的本地链路，不调用 ComfyUI。
- 主模型：NomosWebPhoto ESRGAN、NomosWebPhoto RealPLKSR；极速：NomosUni SPAN multijpg；可选细节：UltraSharp V2 Lite / DAT2；预处理：DeJPG；另有人脸专用分支。
- 上述主模型、极速模型、DeJPG、两款 UltraSharp 均在本机 `models/sr`。UltraSharp 不属于默认必跑分支，只有手动提高细节强度才参与，不能把所有问题归咎于多模型融合。
- 现有管线已经有平滑区/硬边保护、保真校正和拼块处理。但主模型的照片取向不等于几何重建；保护边缘也不能确定原始曲线是什么。
- `sr.rs` 还存在 6144 长边的神经输出计算预算：超过预算可能先缩小输入、推理后再缩放。16K 输出尺寸不等于模型直接恢复了 16K 的结构。这是大图验收应覆盖的因素，本次未修改该策略。
- 矢量引擎是 VTracer **0.6.5**，已有多参数候选、渲染回比和几何识别，`flat_art.rs` 也有色盘清理。仅再包装一个相同 VTracer 接口不太有价值，下一步应比较新引擎与现有完整处理链。
- 注册表记录 UltraSharp 权重为 CC-BY-NC-SA-4.0；引擎代码许可与模型权重许可需要分别核对，不能因推理框架可商用就把所有权重随包发布。

## 公开矢量项目

| 项目 | 已核实能力 | 对 MOMO 的选择 |
| --- | --- | --- |
| [VTracer](https://github.com/visioncortex/vtracer) | Rust/CLI，彩色轮廓转 SVG；当前 1.0 分支新增固定色盘、共享边界、watershed、曲线简化 | 最值得优先比较的轻量本地方案。正式项目仍为 0.6.5；[1.0.0-alpha.4](https://github.com/visioncortex/vtracer/releases/tag/1.0.0-alpha.4) 是预览版，本次只在隔离目录实测 CLI |
| [StarVector](https://github.com/joanrod/star-vector) | 1B/8B 图像生成 SVG 代码，支持图标、标志、图表等 | 作为结构化图形候选。官方明确不适合自然照片或普通插画，不能当任意海报转换器 |
| [OmniSVG](https://github.com/OmniSVG/OmniSVG) | 公开推理代码与 1.1 4B/8B 权重，面向较复杂 SVG 生成 | 可实验复杂插画重构，优先级低于几何保真。官方示例显存约 17G/26G，并非本机实测；生成结果仍需检查形状、文字与遮挡 |
| [SvgBot](https://github.com/jamesmudgett/svgbot) | 作者组合 VTracer、StarVector、多候选感知评分、残差补丁和曲线平滑 | 符合「几个模型搭配」的公开参考，尚未在本机运行；其“最准确”是作者描述。本项目已有部分候选评分机制，应借鉴缺失部分，避免重复套壳。仓库为 GPL-3.0 |

所有生成式 SVG 都需要回渲染比较，尤其检查字形、内部孔洞、尖角和相邻色块接缝。把位图内嵌进 SVG 容器不属于这里讨论的矢量重建。

## 不依赖 ComfyUI 的放大候选

| 候选 | 优先比较的权重/任务 | 接入方式与边界 |
| --- | --- | --- |
| [HAT / HAT-S](https://github.com/XPixelGroup/HAT) | 经典超分的保真权重，另把 Real HAT 与 sharper 权重分开测 | 官方支持独立 PyTorch 推理与 tile；不要默认选名称带 sharper 的分支 |
| [SwinIR](https://github.com/JingyunLiang/SwinIR) | classical SR；输入确有 JPEG 压缩时再比较对应去压缩模型 | 独立推理，适合作稳定基线；不同退化任务需要对应权重 |
| [DRCT / DRCT-L](https://github.com/ming053l/DRCT) | 常规超分 / MSE 路线，与 GAN 版本区分 | 官方独立脚本；有 ONNX 相关实现不等于任意权重已经兼容 MOMO 的 DirectML 与动态分块 |
| [Spandrel](https://github.com/chaiNNer-org/spandrel) | 加载 HAT、SwinIR、DRCT 等架构 | 它是权重加载框架，不是放大模型。可用独立 Python worker 接 MOMO，无需启动 ComfyUI；权重仍逐项校验许可与来源 |

这三类新模型本次完成源码/官方能力核查，尚未下载并运行其权重；不能声称它们在你的图片上已胜过现有模型。建议先测 HAT 保真与 SwinIR，再决定是否需要 DRCT；不同时串联三套模型。

## 已做的小样例实测

运行 `python scripts/qa/flat-vector-bench.py`，再打开 `/scripts/qa/flat-vector.html`。使用系统独立 Python 3.14、ONNX Runtime CPU、已安装的两份 ONNX 权重与官方 VTracer CLI；未启动或调用 ComfyUI。CLI 下载 SHA-256 与发布页一致：`8eadb5529864265f003f791ad9cb128e1b9b8b8af8c21016f38b04706bcf3531`。

人工绘制圆环、斜边、圆角与「文化 · 共生」，生成 512×384 真值，再下采样到 128×96。输出都比较 512×384。固定色盘来自已知真值，属于人工提供先验，不能代表全自动分析效果。SVG 由浏览器 Canvas 重渲染。

| 方法 | 平均 RGB 绝对误差（0–255，低为好） | 运行耗时 |
| --- | ---: | ---: |
| Lanczos | 3.068 | 未单独计时 |
| NomosUni SPAN 裸权重 | 5.862 | 0.183 s |
| NomosWebPhoto ESRGAN 裸权重 | 4.153 | 3.428 s |
| VTracer 1.0 默认 | 4.957 | 0.046 s |
| VTracer 1.0 固定色盘 | 4.464 | 0.044 s |
| VTracer 1.0 固定色盘 + 共享边界 | 4.327 | 0.034 s |

肉眼检查发现：两份裸超分权重出现不同程度的边缘亮圈；矢量结果减少此类亮圈，但低分辨率轮廓仍可能歪曲、尖角变圆，不能保证准确恢复圆形。固定色盘比默认候选更接近本样例，并没有全面超过插值基线。

这只是 **1 张合成图、2 份裸模型权重、3 个新矢量参数候选**，没有运行 MOMO 完整保真校正/分块管线，也未比较 VTracer 0.6.5 全管线。整体像素误差会受大片背景支配，不代替文字正确率、边界误差和视觉评审。结论是有必要按内容分路，不能据此宣布某新模型最好。

后续真实样本比较：干净纯色墙、JPEG 墙面图、照片+文字海报各一张；统一 4× 和同一目标像素尺寸，记录边缘亮圈、孔洞保留、文字逐字正确、色差、SVG 节点数量、显存与耗时；另测输入跨分块边界、大于计算预算的输出。用户尚未提供本轮有马赛克的原图，具体故障来源未确诊。
