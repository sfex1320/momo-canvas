# 助手分流、模型分组与 ComfyUI 直启

## 原因与修复

旧 Agent 的系统规则明确要求首轮及修改都撰写完整成品提示词；同时 Codex 会按参考图片指纹续接历史图片会话，旧画面描述可能继续影响本轮。现在区分三个入口：

- 生图：理解需求并形成生成方案，确认后出图；原有视频创作能力保留。
- 编辑：原图＋本轮修改原文直接交给图片服务，跳过对话扩写、品牌模板、旧生成词。缺图阻止执行，取消确认立即结束；结果上的“编辑这张图”会切换编辑模式并绑定该图。编辑节点重试同样保持原文。
- 对话：只走文字/视觉对话通道，不执行图片生成。Codex 快捷按钮只选择模型，保留当前模式。

编辑请求带 operation=edit，Codex 强制新建独立图片会话，附简短编辑任务说明和修改原文；生图任务明确标识 generate。没有新增或改变图片服务商的付费接口协议。

## 模型列表

设置 → 模型配置 → 模型列表切换模式 → 按中转站合并模型。

默认沿用平铺。开启后服务商为一级、模型为二级；悬停或点击进入侧边列表，空间不足时向左展开。画布、助手、默认模型和备用模型都使用同一 ModelPicker。旧配置及导入配置统一补默认值。

## ComfyUI 直启

选择目录后增加“直接启动 ComfyUI（完整节点）”，调用便携包自带 Python 与主程序，不打开绘世界面，不附加禁用全部自定义节点的参数。读取绘世配置里的端口，复用现有模型路径配置。旧绘世绑定在同目录发现唯一直接运行环境时自动升级。

此方式依据 [ComfyUI 官方便携版启动说明](https://docs.comfy.org/zh/installation/comfyui_portable_windows)：便携版启动脚本实质是调用包内 Python 执行 ComfyUI/main.py。无需另装启动器或下载另一个 ComfyUI。

启动日志：AppData/site.jinpengi.momo/comfy-startup.log。探活成功才显示已连接，等待上限 5 分钟。绘世自身的补丁/依赖修复功能不等于服务启动；节点依赖错误仍需查看日志。

## 验证

- `node scripts/test-agent-routing.mjs`：真实助手引擎＋隔离服务替身，覆盖修改原文、指定参考图优先、旧长提示词排除、取消编辑、缺图阻断、纯对话、生图规划和编辑节点属性；不调用收费模型。
- 浏览器预览：配置两个测试模型，开启分组，打开二级菜单并成功选择第二个模型；编辑页显示独立模式及修改原文提示。测试配置只存在浏览器预览，未改桌面服务商配置。
- Rust 本机直启验收：`G:\ciomfyui AI\ComfyUI-aki-v3`，隔离端口 8910，约 120 秒后 `/system_stats` 返回成功；验收结束只关闭测试创建的进程。日志有原安装包的节点加载及数据库占用警告，因此服务连通不代表每个自定义节点都验收通过。
- 本轮没有请求真实 Codex 图片生成；执行正文通过隔离链路检查，实际编辑画面质量仍取决于模型返回。
